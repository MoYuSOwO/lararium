# Lararium

**一个住在你自己服务器上的生活助手。** 在一个聊天窗口里记账、查账、管待办——
你的数据待在你的机器上,不经过任何第三方服务。

`Python 3.12+` · 自部署 · 接任意 OpenAI 兼容模型

> 罗马人家里供家神(Lares)的小神龛,叫 lararium。管这个家的日常。

---

## 它是什么样的

```
你 > 打车 28,记一下
它 > 记上了,交通 28 元。

你 > 昨天中午吃饭也是 45
它 > 记上了,昨天午饭 45 元。

你 > 这个月吃饭花了多少
它 > 这个月餐饮花了 128 元(3 笔)

你 > 我房租每月 3800
它 > 记下了。这个我没当流水记,记成了一条稳定安排

你 > 这个月最大的一笔是什么
它 > 最大的是两顿午饭并列 45 元。
     不过房租 3800 我只是记成了固定安排、还没作为流水记账,
     如果这个月已经付了告诉我,那就是本月最大的一笔
```

最后那一段不是话术——它理解**一次消费**和**一条长期安排**是两回事,并且主动指出
这个区别会影响你刚才那个问题的答案。

## 有什么不一样

市面上"把 AI 接进聊天软件"的项目很多。这个项目关心的是另一组问题:
**它能不能真的记住你、能不能长期用得起、以及它记住的东西可信不可信。**

### 记忆是有闸门的

助手想记住关于你的事,得**先提交、你点头才算数**。它不能自己往你的档案里写东西。

这不是产品洁癖。助手会读到各种东西——转发的短信、网页内容、别人说的话。
如果它能把读到的任何一句直接写进长期记忆,那么**一条精心构造的短信就能永久改写它对你的认知**。
所以写入只有一条路径,而那条路径上站着你。

### 上下文是冻结的,所以长期用得起

对话上下文分六层,前三层逐字节稳定、永不改写,后三层只追加:

```
0  工具定义        ┐
1  人设 + 领域目录  ├─ 冻结前缀:每轮字节完全相同
2  你的档案        ┘
3  历史压缩索引    ┐
4  近期原文对话     ├─ 只追加,不改写
5  当前这一条       ┘
```

这个结构直接吃满 provider 的前缀缓存。**实测七轮对话缓存命中 94.3% → 91.4%,
中途零重建。** 意思是聊得越久,每轮反而越便宜——而不是常见的那种越聊越贵。

代价是纪律:任何随轮变化的东西(时间戳、随机数)都不许进前缀区,写代码时得一直守着。

### 一个脑子,不是一群

主控持有全部智能;每个生活领域是独立模块,只提供工具和数据、**不含 LLM**。
加一个领域 = 往 `bundles/` 扔一个目录,注册代码一行不用改。

多 agent 互相传话的方案试过,推翻了——脑子之间传话必丢、交接必漏,那是结构性故障。

### 外部内容不会被当成你说的话

转发进来的短信、抓来的网页,在上下文里**有明确的来源标注和围栏**,并且在代码层面
被强制降级——它们提出的任何记忆写入都必须经你审批,模型无权自行放行。

## 快速开始

需要 [uv](https://docs.astral.sh/uv/)。

```bash
git clone <repo> && cd lararium
uv sync
cp .env.example .env      # 填模型 API key(任意 OpenAI 兼容端点)

# 语义检索的权重转一次(一次性,之后不再联网;不转也能跑,只是没有语义检索)
uv run python scripts/build_embedding_weights.py
```

> 权重转成 fp16 + mmap 加载,是为了能跑在 2C2G 的小机器上:加载峰值从 1772 MB 降到
> 972 MB。质量代价实测为零(相似度漂移 0.00006,而判定阈值的决策余量是 0.09)。

两个进程:常驻服务 + 客户端。

```bash
# 终端 A —— 服务
set -a && source .env && set +a \
  && LARARIUM_TOKENS=cli:tok-dev LARARIUM_INGEST_TOKENS= \
  && uv run python -m lararium.gateway.server
```

```bash
# 终端 B —— CLI 客户端
export LARARIUM_SERVER_URL=http://127.0.0.1:8420 LARARIUM_CLIENT_TOKEN=tok-dev
uv run python -m lararium.gateway.cli
```

对话里可用的命令:`/pending` 看待审记忆、`/approve <id>` 批准、`/reject <id>` 否决、
`/settle` 落盘、`/ledger` 打印档案、`/history` 看快照、`/rollback <id>` 回滚、
`/replay <id>` 逐字重放某一轮。

审批只能由你来——**这些是代码路径,不是模型能调的工具**。

### 给它换个性格

性格放在 `{data_dir}/character.md`,直接编辑就行(不存在则用内置默认)。
系统纪律单独放在 `prompts/discipline.md`——两者拆开,是为了让你改性格的时候
不会顺手把纪律删掉。

性格**只能改文件,不能在对话里让它改自己**:模型能写前缀,等于给提示注入开了一条直通车。

## 现在能做什么

| | |
|---|---|
| ✅ **记账** | 对话式记一笔,固定类目,金额存整数分 |
| ✅ **查账** | 按类目/按天聚合,返回结论不返回流水 |

| ✅ **上下文压缩** | 聊到超窗自动压缩,两道审批屏障 |
| ✅ **夜间归拢** | 后台扫历史,补上漏记的事 |
| 🚧 **上手机** | 目前只有 CLI,IM 适配器在做 |
| 🚧 **账单自动入账** | 短信/支付通知的数据面 |
| 🚧 **部署** | 容器化与运维 |

## 架构

```
src/lararium/
  steward/        主控 —— 唯一持有智能的地方
    ports.py        对模块的抽象(守住 import 边界)
    inbox journal   收件箱、起居注
    assembler       上下文组装(那六层)
    loop            一轮的编排
  gateway/        HTTP 服务 + CLI 客户端
bundles/
  memory/         账本 + 门控状态机
  finance/        记账与消费分析
```

边界由 [import-linter](.importlinter) 强制,四条契约:主控不许依赖任何模块、
模块不许反向依赖主控、模块之间互不依赖、CLI 是纯 HTTP 客户端。
需要某个模块的能力就走 `ports.py` 的 Protocol,由组装根接线。

**进过模型上下文的一切都落起居注**,而且落的是模型实收的那一份——任意一轮都能逐字重放。

设计取舍与决策记录见 [DESIGN.md](DESIGN.md)。

## 开发

```bash
uv sync && uv run pre-commit install
```

提交前门禁(pre-commit 也会跑):

```bash
uv run ruff check src bundles tests && uv run ruff format --check src bundles tests && uv run mypy && uv run lint-imports && uv run pytest -q
```

四关:ruff(lint + 格式)、mypy(分层严格)、import-linter(架构边界)、pytest。
当前 **367 passed**;标 `-m live` 的是真模型验收,没有 API key 会自动跳过。

开发规范见 [CONVENTIONS.md](CONVENTIONS.md)——只收"防真实腐烂、而机器判不了"的那些,
不重复 linter 已经能管的事。
