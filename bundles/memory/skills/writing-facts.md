# 怎么写账本条目

## 事实是**归纳出来的短句**,不是用户的原话

原话是证据,归纳才是事实。照着原话抄一条上来等于什么都没提——账本里躺着一句
「哎这破天气 又下雨 我那车停外面一晚上全是泥点子」,三个月后没有任何人能拿它做任何事。
**同一句话里可以有不止一条事实,也可能一条都没有。**

```
「哎这破天气……我那车停外面一晚上」        → ✓ 有车 / ✓ 车停在户外
「我妈住我们楼下,天天上来送汤」            → ✓ 母亲住同一栋楼
「昨天球赛没看成,反正也不是主队」          → (一条都没有:一时之事 + 派生结论)
「跟组里那帮人聚餐我一般不去,我不喝酒」    → ✓ 不喝酒
```

一条一个事实,短句,不加时间前缀(快照表已经记了时间)。

## 四个判据(四个都是"是"才入账)
1. 是关于用户本人的**一手事实**吗?(不是从别的事实推出来的结论)
2. 很多场合用得上,且**预测不了**哪次用得上吗?
3. **三个月后大概率还成立吗?** 不确定就别入档——情绪、一时之念、当天的情况都会变,
   归话头,不塞进账本。每次结算都是一次前缀重建,乱入档是拿缓存换噪声。
4. 是**稳定安排**,不是**单次事件**吗?发生过一次的事(今天打车 28、昨天看了场电影)
   是事件,归对应的领域模块;一直成立的约定(房租每月 3800、每周三练琴)才是安排。
   这条和第 3 条不是一回事:一次性事件即使三个月后回头看仍然"是真的",它也不该入档
   ——账本记的是"他是个什么样的人、有什么长期安排",不是"他做过什么"。

## 正反例
- ✗ "这个月花了八千" —— 派生数据,财务模块随时能算
- ✗ "今天打车花了 28" —— **单次事件**,走 `finance__record_expense` 记进 finance,不进账本;
  记完账**不要**再 propose 一遍(判据 4)
- ✗ "离健身房近" —— 从住址推出来的结论,现推即可
- ✗ "今天心情不好" —— 会变,留在对话里/归话头
- ✗ "想做红烧肉" —— 一时之念,下礼拜可能就不想了,归话头而不是入档
- ✗ "他说'那天天上课睡觉'" —— **原话**,不是事实;该写成 ✓ "在上学"
- ✓ "房租每月 3800" —— **稳定安排**,该入档;边界是"流水不进",不是"钱的事都不进"
- ✓ "对芒果过敏" / "妻子叫小雨" / "住在望京" / "在备考雅思"

## 提交(只有对话里用得上,归拢没有工具)
- 归到正确的小节:身份 / 关系 / 长期偏好 / 正在进行
- 改变已有事实用 amend(带 old_text 精确匹配),事情结束用 retire
- 共享实体用 [[链接]] 引用,例如 "住在 [[家]]"

## provenance 怎么填
- `user_stated`:用户在对话里亲口说的 → 自动放行,你要在回话里回显一句"已记下:X"
- `untrusted`:来自短信、邮件、网页等外部数据推出的 → 必须用户显式审批,你不能替他决定
