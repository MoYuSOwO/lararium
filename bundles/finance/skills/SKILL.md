# finance —— 记账与消费分析

finance 有自己的库(不进 Steward 的存储),记录每一笔消费。记账、查账、看这个月某类
花了多少,都走 finance 的工具——**别把这些流水记进账本**。账本是关于你的月级事实
(「房租每月 3800」),流水是每一笔消费;账本每轮全量注入、记一笔就是一次结算。

## 什么时候用
- 用户报一笔开销 → `record_expense`
- 用户问某段时间某类花了多少 → `query_spending`(返回结论,不返回单笔流水)
- 用户问最近花了些什么 → `list_recent`(**最近**的若干笔,硬封顶 20;
  它给不了"整个月最大的一笔",别拿它冒充)
- 想系统地看一个月 → 先 `read_skill("finance", "monthly-review")`

## 查账怎么问

`query_spending(since, until, group_by)`:since/until 都是 YYYY-MM-DD、**两端都含**;
group_by 只有 `category`(按类目)和 `day`(按天)。返回的是**总额 + 每组一行结论**。

- 按类目:金额从高到低——哪一类吃掉了预算,第一行就是答案。
- 按天:**时间正序**,整月(31 天)原样装得下,可以直接读趋势。区间再长时会砍掉
  最早那段、合并成一行「更早 N 天合计」放在最前面。

总额那一行**始终是全区间的**,和有没有截断无关。它**不会**给你单笔流水——
要看单笔用 `list_recent`。

## 时间怎么来

"昨天""上周三""这个月初"这类相对时间,**先调 `current_time` 拿到今天是几号,自己换算成
具体日期再传**。finance 是纯函数、零 LLM,它没有"今天是几号"的概念:`occurred_at` 只认
YYYY-MM-DD 或 YYYY-MM-DD HH:MM,看不懂会原样退回来、那一笔不会被记。
用户没提时间就别传这个参数——缺省就是现在。

## 记完账之后
不要把刚记的流水再 propose 进账本。流水进 finance,只有**稳定的安排**(每月固定支出、
某个长期习惯的花费规律)才进账本。
